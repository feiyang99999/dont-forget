# 到期管家

给一个人用的到期与续费提醒。保单、证件、合同、账单和订阅记在自己的 iPhone 上，不注册，不上传，也不用付费服务。

识别、存储、搜索都在浏览器里完成。可以做成纯静态网站，放在 GitHub Pages 的子路径下（构建用相对路径）。

## 能做什么

- 拍照或从相册选一张单据，在手机里用 Tesseract.js 做中英文识别，并显示进度。
- 用规则猜名称、类别、金额、货币、生效日和到期日。你改完再保存。
- 原文整段保存，并留一张缩小的照片。规则猜错了，可以按原文再提取一次。
- 按人（我、伴侣、孩子、父母，可改名）和类别筛选，也能搜索原文。
- 续期时旧的一份留在时间线上，不会被盖掉。
- 订阅记下价格和每月/每年，年费折成每月，看每月合计。
- 默认在到期前 30 天、7 天、1 天提醒。点一下导出 `.ics`，交给 iPhone 的日历去响铃。打开应用时，7 天内到期的会有一条提示。
- 全部存在 IndexedDB。可以导出 / 导入 JSON 备份。

界面默认中文，可以切到英文。布局按 iPhone 的安全区留出边距，按钮够大。

## 隐私

没有账号，没有统计，没有后端。页面加载完成之后，不再访问第三方。识别引擎和中英语言数据随这个网站一起提供（大约 16MB 放在站点里，一台手机第一次识别实际下载其中约 9MB），之后由浏览器缓存。

日历文件里只有名称、人和日期，不写证件原文，避免你打开 iCloud 日历后把原文同步出去。

## 本地运行

需要 Node.js 22。

```bash
npm install
npm test
npm run dev
```

浏览器打开终端里给出的地址。`npm run dev` 会先把 OCR 文件从依赖包复制到 `public/ocr/`（这个目录不提交到 git）。

生产构建：

```bash
npm run build
npm run preview
```

默认 `base` 是相对路径 `./`，所以放在 `https://用户名.github.io/仓库名/` 下面也能找到脚本和图标。如果主机要求绝对前缀：

```bash
BASE_PATH=/仓库名/ npm run build
```

`BASE_PATH` 要以 `/` 开头和结尾。

## 免费部署到 GitHub Pages

1. 把这个项目推到一个 GitHub 仓库。
2. 打开仓库的 Settings → Pages。
3. Build and deployment 里，Source 选 GitHub Actions。
4. 推送到 `main` 后，`.github/workflows/pages.yml` 会跑测试、构建，并发布 `dist`。
5. 等 Actions 变绿。页面地址一般是 `https://用户名.github.io/仓库名/`。

仓库名就是子路径。不用改代码，相对路径已经按这个情况准备好了。

## 在 iPhone 上安装

1. 用 **Safari** 打开上面的网址（不要用微信内置浏览器）。
2. 点底部分享按钮。
3. 点「添加到主屏幕」。
4. 以后从图标打开。第一次识别需要联网，把语言数据缓存进手机；之后清单可以离线打开。

## 提醒怎么工作

网页自己没法在 iPhone 上可靠地定时响铃。iOS 16.4 以后，加到主屏幕的网页可以收 Web Push，但必须有一台服务器发推送。这个项目没有服务器，所以不做网页推送。

可靠的办法是日历：

1. 在单据上点「加入日历」，或在设置里「导出全部日历提醒」。
2. 打开下载的 `expiry-butler.ics`。
3. 选择加入日历里的全部事件。
4. 在系统设置里允许「日历」发送通知。

事件写在到期日（或下次扣款日）上午 9 点，另外按你勾选的天数提前响（默认 30、7、1）。时区跟着手机走，文件里没有写死某一个时区。

重新导入可能生成重复事件，删掉旧的再导入即可。续期之后，如果日期变了，需要再导出一次。

订阅的下次扣款日如果已经过去，打开应用时会自动推到下一期，这不算一次「续期」，时间线不会多一条。换了新保单、新证件，用「续期」，旧原文会留下。

## 识别准不准

规则能认这些日期：`2026-10-22`、`2026/10/22`、`2026.10.22`、`22/10/2026`、`Oct 22, 2026`、`22 Oct 2026`、`2026年10月22日`，以及「有效期至」「到期日」「截止日期」「expiry」「valid until」「due date」「renewal」这类旁边的词。

`01/02/2026` 这种两个数字都不大于 12 的，按日/月/年理解（2 月 1 日）。`10/22/2026` 因为 22 不可能是月份，按月/日/年。

照片请尽量正、亮、字大。识别结果一定先给你改，再保存。原文会留着，可以再提取一次。

## 人和类别

默认有四个人：我、伴侣、孩子、父母。设置里可以改名、加人。还有单据挂在某人名下时，不能删这个人。

这是向本地记忆项目 [MemPalace](https://github.com/MemPalace/mempalace) 借的收纳办法，缩小之后放在手机上：一个人是一翼，一类单据是一室，每张单据连同原文是一屉。没有向量数据库。搜索是名称、备注、原文和历史原文里的字面匹配，可以按人和类别缩小范围，不懂「意思相近」。

## 测试

```bash
npm test
```

覆盖提取规则、日期和扣款日推算、`.ics` 提醒，以及 IndexedDB 与 JSON 备份的往返（原文、缩略图、历史版本都要还在）。

## 限制

- 识别会认错，尤其是模糊、折角、手写和复杂表格。
- 没有网页推送。提醒靠系统日历。
- iPhone 存储不够时，可能清掉网站数据。主屏幕图标更稳一些，但仍要偶尔导出备份。
- 缩略图不是原图。原图不长期保存，原文文字会保存。
- 第一次识别要读大约 9MB 的本站文件。完全离线之前，需要先打开过一次并成功识别过。
